# Module 2 Implementation Plan

**Goal:** Deliver a working backend compatible with Modules 1, 3 and 4 and explain its implementation to the user.

**Architecture:** Domain routers and services share typed SQLAlchemy models, authorization dependencies, error handling and serializers. External face verification is isolated behind an HTTP client. Production policies remain separate from explicit isolated public-test compatibility.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, PostgreSQL, Redis, bcrypt, python-jose, HTTPX, pytest.

**Spec:** `docs/superpowers/specs/2026-09-11-module2-design.md`

## Global constraints

Use `/api/v1`, access-token TTL 3600 seconds, refresh-token TTL 604800 seconds, HS256, bcrypt >=10, UUID identifiers, no stored images, normalized foreign-key relationships, request IDs and consistent errors. Maintain current client request/response names. Do not change provided public tests or unrelated Module 3 implementation.
